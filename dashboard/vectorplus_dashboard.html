🅱 BM25 via pg_textsearch Industry-standard relevance ranking as a Postgres index AM ▼
ts_rank_cd scores on term frequency within a document. BM25 adds inverse document frequency, term-frequency saturation and length normalization from corpus-wide statistics — the same ranker Elasticsearch and Lucene use. The index goes on the same text the tsvector column covers, so the two are compared on identical input.

k1 controls term-frequency saturation, b controls length normalization. force_merge is the equivalent of Lucene’s forceMerge(1) — it collapses the LSM segments left over from the bulk load into one.

🧪 Filtered queries The filter runs after the index scan — a selective one returns short
Filtering is applied after the index scan, as with pgvector's IVFFlat. There are no index-only, bitmap or parallel index scans, so a WHERE clause is always applied afterward. Two fixes: a partial index, or a wider probes.

🩺 Index health & drift Clustering happens once, at build time — the table drifts away from it
index_health = (1 − pct_pending) × (1 − pct_dead_lanes). It is 1.0 on a fresh build; below 0.8 the function emits a NOTICE recommending REINDEX INDEX CONCURRENTLY. REINDEX is the only operation that repacks append-region rows and reclaims dead lanes.

🧾 Every statement this app has run Searches, hybrid legs, index builds, REINDEX and the SQL editor
Each statement is written to a text file you can tail -f and to the results store, so the SQL is recoverable after the fact instead of vanishing when you switch tabs. What counts as worth logging is judged from the statement itself, not from which function issued it: anything touching embedding, tsv or a distance operator is kept, while catalog lookups, current_setting, row counts and health probes are treated as metadata and suppressed unless you switch the level. Press full on any row to get the statement with the query vector substituted in, runnable in psql as-is. A recall sweep is recorded once as a summary rather than as its hundreds of near-identical statements.
